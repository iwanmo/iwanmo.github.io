## Abstract

### 아이디어

- 배경
  - 레이블 없는 대규모 텍스트 코퍼스는 많다.
  - 학습에 쓸 레이블이 달린 데이터는 부족하다.
- 해결법
  - 레이블 없는 텍스트로 언어 모델을 생성적(generative)으로 사전학습한 뒤,
  - 각 특정 작업에 대해 판별적(discriminative)으로 미세 조정해서 이득을 본다.
  - 파인튜닝 시 태스크에 맞게 입력을 변환한다 (task-aware input transformations).

### 결과

- task-agnostic model이 우수했다.

## 1. 서론

### 배경

- 사전학습된 임베딩은 사람이 어노테이션을 단 것이 아니다.
- 레이블이 없는 원시 텍스트로 학습하는 능력은 지도 학습에 대한 의존성을 줄이는 데 중요하다.
  - 레이블링에는 시간과 비용이 든다.

### 어려움

> 단어 수준을 넘어선 표현, 즉 문장·문맥 수준의 표현을 unlabeled 텍스트로부터 배우는 게 어렵다.
>
> 기존에 단어 임베딩은 비지도 학습으로 잘 학습되었지만, 문장이나 문단은 그렇게 쉽지 않다는 뜻이다.

**1. 어떤 목적 함수를 써야 하는가**

- 비지도로 표현을 배우려면 레이블 대신 모델이 풀어야 할 문제를 정의해 줘야 한다.
- 어떤 문제를 풀게 해야 전이(transfer)에 유리한 표현이 나오는지 불분명하다.
  - **Language modeling**: 다음 단어 맞히기 (예: ELMo, 그리고 GPT 자신)
  - **Machine translation**: 번역 과정에서 얻은 인코더 표현 사용 (예: CoVe)
  - **Discourse coherence**: 문장들의 순서·연결 관계가 자연스러운지 판별

**2. 학습한 표현을 타깃 태스크로 어떻게 옮길까**

표현을 배웠어도, 이걸 실제로 풀고 싶은 태스크에 어떻게 붙여 쓸지에 대한 정해진 방법이 없다. 당시에 쓰인 방법은 다음과 같다.

- **태스크별 아키텍처 변경**: 태스크마다 모델 구조를 따로 설계해 사전학습된 표현을 끼워 넣기
- **복잡한 학습 스킴**: 레이어별로 learning rate를 다르게 주거나 단계적으로 풀어주는 등 정교한 절차 필요
- **보조 학습 목표 추가**: 메인 태스크 손실에 부가적인 unsupervised 손실을 같이 얹어 학습

### 아이디어

- 비지도 사전학습과 지도 파인튜닝을 결합한 준지도 학습(semi-supervised) 접근 방식을 탐구한다.
- 목표는 적은 조정으로 광범위한 태스크에 전이되는 보편적인 표현을 학습하는 것이다.

### 방법

**1. Unsupervised pre-training**

- 레이블 없는 대량의 텍스트에 language modeling 목적 함수를 적용해 신경망의 초기 파라미터를 학습한다.
- language modeling: 지금까지의 단어들을 보고 다음 단어를 예측하라.
- 즉 사람이 단 레이블 없이 텍스트 자체가 곧 정답이 되는 자기 지도 학습이다.

$$
L_1(\mathcal{U}) = \sum_i \log P(u_i \mid u_{i-k}, \dots, u_{i-1}; \Theta)
$$

- 앞의 k개 단어가 주어졌을 때 다음 단어 $u_i$의 로그 확률을 최대화한다.

**2. Supervised fine-tuning (미세 조정)**

- 1단계에서 얻은 파라미터를 **그대로 가져와서 시작점으로 삼는다**.
- 풀고 싶은 실제 태스크(분류, 함의 판단, 질의응답 등)의 레이블 데이터로 추가 학습한다.
- 모델을 처음부터 다시 학습하는 게 아니라, 기존 언어 모델을 해당 태스크에 맞게 살짝 조정한다.
- 장점
  - 목적 함수 문제 해결
    - 언어 모델로 통일한다.
    - 데이터가 많고, 다양한 태스크에 두루 유용한 표현을 만든다.
  - 전이 방식 문제 해결
    - 같은 모델(Transformer)을 가져와서 지도 학습 목적 함수로 학습한다.
    - 태스크별로 구조를 새로 짜거나 복잡한 학습 스킴이 필요 없다.

> **학습 스킴**: 모델을 어떻게 학습시킬지에 대한 절차나 전략, 레시피
{: .prompt-tip }

→ 기초 없이 바로 전문 교육을 받는 것보다, 일반 교육을 충실히 받은 사람을 데려다 전문 교육을 시키는 게 훨씬 효율적이고 결과도 좋다.

**3. 전이 학습 시 입력 변환**

- 태스크마다 입력을 적절히 바꿔주는 방식을 쓰는데, 이건 traversal-style 접근법에서 따온 것이다.
- 여러 부분으로 나뉜 입력을 하나의 이어진 토큰 시퀀스로 만들어서 처리한다.

→ **여러 조각으로 된 입력을 한 줄로 이어 붙여서 모델에 넣는다.**

## 3. 프레임워크

두 단계로 이루어진다.

- 대규모 텍스트 코퍼스로 고용량 언어 모델을 학습한다.
- 지도 학습으로 태스크에 맞춰 파인튜닝한다.

### 3.1 Unsupervised pre-training

코퍼스 토큰 $\mathcal{U}$에 대해 다음을 최대화한다.

$$
L_1(\mathcal{U}) = \sum_i \log P(u_i \mid u_{i-k}, \dots, u_{i-1}; \Theta)
$$

- 즉 a가 주어졌을 때 b가 나올 확률, a, b가 주어졌을 때 c가 나올 확률, …
- k는 컨텍스트 윈도우다.
- 조건부 확률 P는 파라미터 $\Theta$를 가진 신경망이다.
- 경사하강법으로 학습한다.

언어 모델로는 트랜스포머 디코더를 사용한다.

$$
\begin{aligned}
h_0 &= U W_e + W_p \\
h_l &= \mathrm{transformer\_block}(h_{l-1}) \quad \forall l \in [1, n] \\
P(u) &= \mathrm{softmax}(h_n W_e^\top)
\end{aligned}
$$

→ 입력 토큰에 multi-head attention 연산을 적용한 뒤, 토큰에 대한 출력 분포를 만든다.

**1. 입력 임베딩: $h_0 = U W_e + W_p$**

- 입력 토큰 $U$에 $W_e$를 곱해 임베딩 벡터로 바꾸고, $W_p$로 위치 정보를 더한다.
  - $W_e$는 토크나이저와 짝을 이루는 임베딩 테이블이다.
- 이때 임베딩 $W_e$와 위치 값 $W_p$는 모두 학습된다.
  - 이 부분이 원조 Transformer의 위치 벡터(sin, cos 고정값)와 다른 점이다.

**2. 블록 통과: $$h_l = \mathrm{transformer\_block}(h_{l-1})$$**

- l이 1부터 n까지의 모든 값에 대해, $h_l$은 $h_{l-1}$을 transformer block에 통과시킨 결과다.

**3. 출력 확률 계산: $P(u) = \mathrm{softmax}(h_n W_e^\top)$**

- $h_n$: 마지막 레이어를 통과한 hidden state
- $W_e^\top$: 토큰 임베딩 행렬의 전치
- 출력용 행렬을 따로 두지 않고 입력 임베딩을 다시 쓰는 이유
  - 출력용 행렬을 따로 두면 파라미터가 늘어난다.
  - 의미적 연관성
    - 입력 시 "고양이"로 임베딩한 벡터와, 출력 시 "고양이"를 예측하는 가중치가 같다.

> ❓ 전치(transpose)는 역행렬이 아닌데 왜 이렇게 쓸까?
>
> → hidden state와 각 단어의 임베딩 값이 얼마나 유사한지를 내적으로 구하는 것. 상관계수처럼 곱해서 비교한다.
{: .prompt-tip }

- 곱한 결과에 softmax를 취해 확률을 반환한다.

**학습 과정의 사이클**

```text
1. 텍스트에서 임의의 위치 선택
   "나는 학교에" (입력)
   "갔다" (정답)

2. 입력을 토큰 ID로 변환 후 임베딩
   [나는, 학교에] → 벡터 시퀀스

3. Transformer Decoder 통과
   12층의 Masked Self-Attention + FFN

4. 마지막 hidden state로부터 어휘 전체에 대한 확률 분포 생성
   {갔다: 0.3, 왔다: 0.1, 들렀다: 0.05, 먹었다: 0.02, ...}

5. 정답("갔다")의 확률을 높이도록 모든 파라미터 업데이트
   (역전파 + 경사하강법)

6. 텍스트의 다른 위치에서 다시 1번부터 반복
```

| 연산            | 입력    | 출력        | 역할                       |
| --------------- | ------- | ----------- | -------------------------- |
| $UW_e$          | 토큰 ID | 벡터        | **인코딩**: 단어 → 벡터    |
| $h_n W_e^\top$  | 벡터    | 단어별 점수 | **디코딩**: 벡터 → 단어    |

- $W_e^\top$를 곱하는 건 "벡터를 다시 단어로 되돌리는" 디코딩 역할이다.

### 3.2 Supervised fine-tuning

**1. 데이터셋 정의**

$$
\mathcal{C} = \{(x^1, \dots, x^m, y)\}
$$

- **입력 토큰 시퀀스**: $x^1, x^2, \dots, x^m$ (예: 문장의 단어들)
- **정답 레이블**: $y$ (예: 긍정/부정, 함의/모순/중립 등)

**2. Forward pass**

- 입력을 사전학습된 모델에 넣어서, 마지막 transformer 블록의 마지막 토큰 위치 활성값을 얻는다.
- $h_l^m$: l번째(마지막) 레이어의 m번째 토큰 위치 hidden state
  - 즉 시퀀스의 마지막 토큰이 모델 끝에 도달했을 때의 표현
  - GPT는 단방향이라 마지막 토큰이 시퀀스 전체를 다 본 상태다.
- 즉 마지막 토큰의 hidden state가 시퀀스 전체를 요약한 표현이다.

**3. 분류기 추가**

$$
P(y \mid x^1, \dots, x^m) = \mathrm{softmax}(h_l^m W_y)
$$

- 마지막 토큰의 표현 $h_l^m$ 위에 새로운 선형 레이어를 얹는다.
- 결과는 각 레이블에 대한 점수 → softmax → 확률
- 즉 사전학습된 transformer 모델에 작은 선형 레이어 하나만 붙인 것이다.

**4. Fine-tuning 목적 함수**

$$
L_2(\mathcal{C}) = \sum_{(x, y)} \log P(y \mid x^1, \dots, x^m)
$$

- 레이블 데이터의 모든 쌍에 대해 정답 확률을 최대화한다.
- P는 softmax 분류기이므로 $h_l^m$과 선형 레이어 $W_y$의 가중치가 학습된다.
  - $h_l^m$은 트랜스포머를 forward pass한 결과이므로 트랜스포머의 가중치도 같이 바뀐다.

**5. 보조 목적 함수**

$$
L_3(\mathcal{C}) = L_2(\mathcal{C}) + \lambda \cdot L_1(\mathcal{C})
$$

- $L_2(\mathcal{C})$: 메인 supervised 태스크 손실 (예: 분류 cross-entropy)
- $L_1(\mathcal{C})$: language modeling 손실. **단, fine-tuning 데이터셋 $\mathcal{C}$ 위에서 계산한다.** (사전학습 때 unlabeled 데이터셋 $\mathcal{U}$ 위에서 쓰던 손실 함수와 같지만, 적용하는 데이터가 다르다.)
- $\lambda$: 보조 손실의 가중치. 논문에서는 0.5를 사용한다. **보조 목적 함수에 얼마나 비중을 둘지** 결정한다.
  - λ가 클수록 언어 모델을, 작을수록 태스크를 중시한다.
- $L_3$: 둘을 합친 최종 손실. 이 값을 기준으로 학습한다.
- 파인튜닝 시 언어 모델링을 보조 목표로 포함하면, 지도 학습 모델의 일반화가 개선되고 수렴이 빨라진다는 것을 발견했다.
- 파인튜닝이 풀어야 할 건 분류지만, 사전학습에 썼던 언어 모델(다음 단어 예측)을 다시 학습에 함께 사용하는 것이다.

### 3.3 Task-specific input transformations

사전학습 모델은 연속된 텍스트로 훈련되었기 때문에, 다양한 태스크에 적용하려면 입력을 수정해야 한다. 특히 구조화된 입력처럼 입력이 여러 부분으로 나뉘어 서로 다른 역할을 하는 경우가 그렇다.

- 예: 함의(전제, 가설), 질의응답(문서, 질문, 답), 유사도(문장 1, 문장 2)

- 이전 연구
  - 전이된 표현 위에 태스크별 아키텍처를 학습하는 것을 제안했다.
  - 문제는 태스크별 맞춤 설정이 너무 많고, 이렇게 추가한 컴포넌트에는 전이 학습의 이점을 쓰지 못한다는 것이다.
- GPT 방식: **모델을 바꾸는 대신 입력을 바꾸자** (traversal-style approach, 순회 방식 접근)
  - 구조화된 입력을 순서가 있는 시퀀스로 변환한다.
  - 입력 변환 덕분에 태스크별 아키텍처 변경을 피할 수 있었다.

### 그림 설명

![12층 Transformer 디코더 구조와, 분류·함의·유사도·객관식 태스크별로 입력을 Start, Delim, Extract 토큰으로 이어 붙이는 입력 변환 방식](/assets/img/posts/gpt1/01_paper_figure1.png){: w="1260" h="654" }
_출처: 논문 Figure 1_

- 특수 토큰
  - **Start**: 새로운 입력 시퀀스의 시작 신호
  - **Delim**: 다른 부분이 시작된다는 구분자
  - **Extract**: 입력이 끝났으니 예측하라는 신호

**Textual Entailment (텍스트 함의)**

- 전제와 가설을 delimiter로 구분만 해서 이어 붙인다.
- 함의는 순서가 의미를 가지므로 한 방향만 처리하면 된다.

**Similarity (유사도)**

- 두 문장 사이에는 순서가 없다.
- 그래서 입력을 두 가지 순서로 만든다.
- 각각 독립적으로 처리한 뒤 element-wise로 더해서 선형 레이어에 넣는다.

> **element-wise 덧셈**
>
> - 두 hidden state를 같은 위치끼리 더한다.
> - 덧셈은 교환법칙이 성립하니 최종 입력값이 같아진다 → 대칭성 보장
> - ❓ 정보가 섞여서 의미가 왜곡되지 않을까?
>   - 트랜스포머에서 multi-head를 합칠 때처럼 concat한 뒤 선형 레이어를 태우는 게 낫지 않을까? → 그러면 순서가 영향을 미친다.
>   - concat을 양방향으로 해서 element-wise로 더하면? → 선형 레이어가 의미를 분리해 줘도, 어차피 더하는 순간 섞이는 건 같다.
>   - 고차원 공간에서 덧셈은 생각보다 정보를 잘 보존하고, 뒤따르는 선형 레이어가 분리할 수 있다.
{: .prompt-tip }

이후에 정보를 뭉개지 않고 합치는 방법들이 나왔다.

- **BERT**
  - 두 문장을 [SEP]으로 연결해 한 시퀀스로 만들고, 그 안에서 양방향 self-attention이 작동해 두 문장의 토큰들이 서로를 직접 참조하게 한다.
  - 합치기 전에 토큰 수준에서 이미 정보가 섞인 상태로 분류 표현이 만들어진다.
  - 그래서 더 정밀한 비교가 가능하고, GPT의 양방향 + 덧셈 방식보다 성능이 좋다.
- **Bi-encoder + Cross-attention 결합**: Sentence-BERT 등은 두 표현을 만든 뒤 더 정교하게 합친다.
- **자연어 프롬프트 (GPT-2/3)**: 아예 합치기 자체를 하지 않는다. "A: [Text 1] B: [Text 2] 이 둘은 비슷한가?"처럼 한 시퀀스로 만들어 모델이 직접 답하게 한다.

## 4. 실험

### Setup: Unsupervised pre-training

- 언어 모델 학습에 BooksCorpus 데이터셋을 사용했다.
  - 출판되지 않은 책들
  - 다양한 장르, 다양한 어휘가 있다.
- 결정적으로 긴 텍스트를 포함해 장거리 정보를 학습할 수 있게 한다.
  - ELMo가 쓴 데이터는 문장 단위로 섞여 있어서 책처럼 긴 문맥이 없다.
  - 결국 긴 문맥이 중요하다.
- 매우 낮은 수준의 perplexity 18.4를 달성했다.

> **Perplexity**: 모델이 다음 단어를 예측할 때 얼마나 헷갈려하는가
>
> - 낮을수록 자신 있게 정답을 예측한다.
> - 예: 1이면 확신, 2면 후보 2개 중에서 고르는 수준, 10이면 평균적으로 후보 10개 중에서 고르는 수준
{: .prompt-tip }

### Model specifications

- 원조 트랜스포머를 기반으로 한다.
- **12층 Decoder-only Transformer**
  - 원조 Transformer의 디코더만 사용한다.
  - 디코더 블록(Masked Self-Attention + FFN)을 12번 쌓은 구조
- **Hidden state 차원 768**
  - 즉 모든 토큰이 768차원 벡터다.
  - 임베딩 차원이자 각 레이어의 출력 차원
- **12 attention heads**
  - multi-head attention에서 head가 12개다.
  - self-attention이 12개의 병렬 head로 나뉘어 작동한다.
  - 768차원을 12로 나누면 head당 64차원이 된다.
  - 각 head는 서로 다른 종류의 패턴을 학습한다.
    - 한 head는 문법적 관계를, 다른 head는 의미적 관계를, 또 다른 head는 멀리 떨어진 토큰 참조를 학습하는 식이다. 12개 head의 결과가 합쳐져 풍부한 표현이 만들어진다.
- **FFN 내부 차원 3072**
  - 각 Transformer 블록 안의 Feed-Forward Network는 768 → 3072 → 768 구조다.
  - 중간 차원을 4배로 늘렸다가 다시 줄이는 형태로, 더 풍부한 비선형 변환을 가능하게 한다.
- GPT-1의 총 파라미터 수는 약 **117M(1억 1,700만)** 정도다.
- Adam 옵티마이저, 학습률 스케줄링
- 100 epoch, minibatch size 64
- 시퀀스 길이 512 토큰
  - 모델이 한 번에 보는 문맥, 즉 컨텍스트 윈도우
- 토크나이저: **BPE**
  - 단어를 서브워드로 쪼개는 토크나이저
  - 자주 같이 나타나는 글자 쌍을 합쳐 하나의 토큰으로 만들고, 이 과정을 정해진 횟수만큼 반복한다.
- Dropout 0.1
  - 학습 중 임의의 뉴런을 10% 확률로 끈다.
- L2 정규화
  - AdamW 방식의 weight decay를 사용한다.
- GELU
  - **Gaussian Error Linear Unit**. ReLU의 부드러운 버전으로, 0 근처에서 부드럽게 변한다.
- 위치 임베딩
  - 원조는 sin, cos 함수를 썼다.
  - GPT는 위치 임베딩을 학습 가능한 파라미터로 만들었다.
- 전처리
  - **ftfy** 라이브러리: 잘못 인코딩된 텍스트를 고친다.
  - 구두점, 공백 표준화
  - spaCy tokenizer로 1차 토크나이징 후, BPE가 서브워드로 쪼갠다.

**사양 정리**

| 항목               | 값                                   |
| ------------------ | ------------------------------------ |
| 아키텍처           | 12-layer Decoder-only Transformer    |
| Hidden dimension   | 768                                  |
| Attention heads    | 12                                   |
| FFN inner dimension | 3072                                |
| Total parameters   | ~117M                                |
| Optimizer          | Adam                                 |
| Max learning rate  | 2.5e-4                               |
| Warmup steps       | 2,000                                |
| LR schedule        | Cosine annealing                     |
| Batch size         | 64                                   |
| Sequence length    | 512 tokens                           |
| Epochs             | 100                                  |
| Weight init        | N(0, 0.02)                           |
| Tokenizer          | BPE, 40,000 merges                   |
| Dropout            | 0.1 (residual, embedding, attention) |
| Weight decay       | 0.01 (non-bias, non-gain)            |
| Activation         | GELU                                 |
| Position embedding | Learned (not sinusoidal)             |

### Fine-tuning details

- 사전학습은 정성껏, fine-tuning은 단순하게
- 나머지 설정은 사전학습과 동일하다.
- **분류기($W_y$)에 dropout 0.1을 추가**
- Learning rate
  - 사전학습보다 4배 작다.
  - 의도적인 선택이다. 이미 좋은 출발점이기 때문에 살짝만 이동한다.
- Batch size 32
- Epoch 3
  - 이미 학습이 되어 있어서 적은 epoch로 충분하다.

### Supervised fine-tuning 결과

**Natural Language Inference (NLI)**

- 자연어 추론 (텍스트 함의 인식)
- 평가 데이터셋

| 데이터셋    | 출처                            | 특징                                |
| ----------- | ------------------------------- | ----------------------------------- |
| **SNLI**    | 이미지 캡션                     | 가장 큰 NLI 데이터셋, 스탠포드 발표 |
| **MNLI**    | 음성 전사, 소설, 정부 보고서 등 | 멀티 도메인, 다양성 강조            |
| **QNLI**    | 위키피디아 (SQuAD 변환)         | 질문-답변 쌍을 NLI 형태로           |
| **SciTail** | 과학 시험                       | 과학 도메인 특화                    |
| **RTE**     | 뉴스 기사                       | 가장 작은 데이터셋                  |

- 출처가 다양해서 모델의 일반화 능력을 검증할 수 있다.
- RTE에서만 졌는데,
  - 샘플이 2,500개 정도로 매우 작다.
  - 작은 데이터에서는 파인튜닝이 어렵다.
- **그 외 5개 중 4개에서 SOTA 갱신**

**Question answering and commonsense reasoning**

- 단일 문장 추론과 다중 문장 추론을 모두 요구하는 태스크(질의응답)
  - 진정한 텍스트 이해가 필요하다.
- RACE 데이터셋
  - CNN이나 SQuAD와 비교하면 단순 추출형이 아니고, 추론이 필요하다.
- 즉 장거리 문맥에 대한 평가가 들어간다.

**Semantic Similarity**

- 양방향 처리 + 덧셈 방식이 실제로 잘 작동함을 증명했다.

**Classification**

- 잘 된다.

### Impact of number of layers transferred

- 레이어를 몇 개 전이하는 게 좋은가? (전이되는 레이어 수의 영향)
- dev set은 validation set을 의미한다.
- 전이되는 층이 많을수록 정확도가 올라간다.
  - 사전학습된 층을 모두 사용하면 정확도가 더 올라간다.

### Zero-shot behaviors

> **Zero-shot**: 모델이 해당 태스크에 대한 학습(fine-tuning) 없이 그대로 수행하는 것
{: .prompt-tip }

- 즉 사전학습만으로 태스크를 얼마나 푸는가
- 가설
  - 사전학습된 언어 모델의 언어 모델링 능력을 높이다 보면, 결과적으로 다양한 태스크의 성능도 좋아진다.
  - 트랜스포머의 attention 메모리가 LSTM보다 전이에 더 도움이 된다.
- x축은 사전학습 업데이트 횟수다.
- LSTM의 분산이 더 크다 → 트랜스포머가 더 안정적이다.

→ 즉 **다음 단어 예측이라는 단일한 목표를 잘 달성하려고 하다 보면, 부수적으로 다양한 추론 능력이 학습된다.**

### Ablation studies

- 절제 실험: 모델의 각 구성 요소가 실제로 얼마나 중요한지 확인한다.
  - 즉 어떤 구조가 GPT를 강하게 만드는가
- 검증 대상
  1. 파인튜닝 시 보조 LM 목적 함수를 뺐을 때
     - 큰 데이터셋은 보조 목적 함수로 이득을 보지만, 작은 데이터셋에서는 의미가 없었다.
  2. LSTM vs Transformer
     - 대부분 트랜스포머가 더 좋았다.
  3. 사전학습을 하지 않았을 때
     - 모든 작업에서 성능이 떨어졌다.

## 6. 결론

우리는 **하나의 범용 모델**을 만들었고, 그 비결은 **language modeling으로 긴 문맥을 사전학습**시킨 다음 **각 태스크에 fine-tuning**한 것이다. 이 과정에서 모델은 **세상 지식과 긴 문맥 처리 능력**을 얻었고, 이게 다양한 NLU 태스크로 잘 전이되어 **12개 중 9개에서 SOTA**를 달성했다.

> **Task-agnostic model**: "태스크에 구애받지 않는 모델"
>
> 분류, QA, 함의 판단 등 어떤 태스크든 같은 모델 구조로 풀 수 있다는 뜻이다. 반대 개념은 task-specific(태스크 전용) 모델이다.
